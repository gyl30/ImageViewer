# 大图库资源整改与最终验收

起点 `72ae1fdcd473fe1076a0cb1d1413f5983b8c0ae0`，main，工作区干净。最终受测版本 `cff34211c30e15d13abca9d606ff1d29789f4612`，正确性、资源和 UI 分开提交。未推送。图库矩阵受测后，仅补充预览加载/失败状态清理及截图等待；图库路径未再改变，预览和全部回归另行复验。

## 方法与适用范围

Linux 6.8.0-138-generic、i7-13700KF、NVMe/ext4、Qt 6.9.3、GCC 16.2、Release、offscreen、DPR=1、1280×800 窗口。原功能基线为 `a85a683`：仅恢复 Release 配置并增加探针，没有资源/UI 优化。完整审查见 [resource-review.md](resource-review.md)，旧九项的原始问题和控制流见 [首次审查](review-2026-10-24.md)。

数据来自本地真实壁纸的 64 个混合尺寸 JPEG 派生样本，尺寸 640×480、480×640、1024×683、800×400；原图 SHA-256 为 `bc9892af3972b8275f9a1b71933b8084af7f94995605b2c14fdcda9d7a4d1b7b`。按 1万/5万/10万/30万路径、每目录 1000 文件生成两组：

- `baseline`/`final`：每规模 N 个目录项，共享 64 个 inode；适合元数据、布局、像素缓存对比，不代表独立文件的冷盘成本。
- `independent-before`/`independent-after`：每规模 N 个独立 inode、不同 JPEG 注释；较小规模跨规模硬链接到最大集合，单个集合内部仍有 N 个不同文件。300000 inode 已实际核对。源内容仍来自 64 个画面，不等同于 30 万张不同相机原片。

每规模 cold 为新进程、空应用缓存；warm 为保留磁盘缩略图的新进程。独立文件 cold 前仅对本数据集逐文件提出 FADV_DONTNEED 建议；不清空全系统缓存，目录项/元数据缓存仍可能命中。以实际 read_bytes 为读盘证据，不将建议当成完全冷盘保证。暖启动也不能跳过全库枚举、排序和读尺寸，项目没有新增持久元数据库。

三段方向交替的遍历，每段 120 个均匀位置，每步 40ms；显式调用同一可见区更新边界并额外渲染 360 帧，再执行 1100/1400/1280 三次变宽和返回顶部。首图字段表示首个与视口相交的成功缩略图到达场景的回调时间，不是整屏全部完成或显示器呈现时间。ready 为扫描及任务空闲，resized 为整个轨迹完成。单次矩阵受调度/页缓存影响，不能把毫秒级差异宣称为统计显著提升。

RSS/PSS/Peak RSS 来自 /proc；进程/线程 CPU 与 I/O 记账为实际采样。进程内存不含整个系统的文件页缓存、显示服务器或 GPU 占用。扫描 CPU 是扫描线程，loader CPU 包括缓存读取、解码、编码与维护；不是调用栈采样。decoded_count 是返回结果数，包含缓存命中和失败；最终探针将成功的可见/预取/过期与失败单列，合计为总数。元数据容量与路径 UTF-16、QImage cache、active pixmap 为逻辑估算；共享图像不能直接相加为物理内存。

## CPU 归因

30 万独立文件首次打开，全轨迹进程 CPU 约 15.37s；扫描线程约 3.94s，缩略图 worker 约 8.96s。三段滚动本身约 10.79s CPU，其中 worker 约 8.86s。变宽、回顶部阶段约 0.11s CPU，其中还包含新尺寸缩略图请求，不能全部算作布局。

主要成本仍在缩略图读写/解码，其次为枚举、排序和读取元数据；编码实验说明 PNG 是其中可避免的一部分。剩余进程 CPU 含 GUI、QtConcurrent 布局和探针，未用调用栈采样独立隔离布局作业，因此不声称已量出纯布局 CPU 或已解决所有格式热点。

## 必需的 O(N) 与固定像素预算

下表取最终独立文件 cold 的 resized 状态。结构包括模型、路径序列槽位和前缀底边索引容量；路径仅计 UTF-16 内容及终止符，不含 Qt 字符串头、malloc 对齐等。因此不能拿两列之和代替 RSS。

| 图片数 | 结构容量 MiB | 路径内容 MiB | QImage 缓存 MiB | 活动项峰值 / 队列采样峰值 |
| --- | --- | --- | --- | --- |
| 10,000 | 0.6 | 0.9 | 64.0 | 25 / 25 |
| 50,000 | 3.2 | 4.6 | 63.9 | 25 / 25 |
| 100,000 | 6.5 | 9.3 | 63.8 | 25 / 25 |
| 300,000 | 19.5 | 28.0 | 63.9 | 25 / 25 |

最终 resized 快照中，活动 pixmap 逻辑像素约 3.6MiB，基线约 9.7–10.0MiB；这些像素可能与 QImage 共享。磁盘缩略图内容约 17.3–17.7MiB、947–968 个文件，基线约 97.0–141.5MiB、1388–2000 个文件；均不含文件系统元数据开销。

随 N 增长的是路径、原始尺寸、布局几何和区间索引；路径长度会直接影响实际内存。排序的临时条目也为 O(N)。图片像素 QCache 硬预算 64MiB，任务队列硬上限 64；活动项由视口和图片密度决定，细长图会容纳更多卡片，不能把本数据集的峰值当成所有格式的固定值。对象池保留历史最大视口需求，回收时释放图片，只保留共享占位图。

64MiB 是缩略图缓存预算，不是整个进程或预览窗口预算；仍有当前 pixmap、正在解码的工作内存及 Qt/allocator 开销。场景和预览共享 QStringList 快照，查找不触发分离；当预览仍浏览旧目录而主窗切到新目录时，旧快照保留到预览关闭，这是导航上下文的所有权。没有新增图库数据库、全量哈希层、线程池或产品配置。

## 持续滚动与清理

30 万独立文件执行 30 段 × 120 位置，共 3600 个滚动位置，保持相同 40ms 间隔。本次图库操作约 156 秒，活动项采样峰值 26、队列峰值 25；可观察缓存填满后的稳定性，不代表数小时验收。

| 阶段 | RSS MiB | PSS MiB | 像素缓存 MiB | 活动项 / 队列 |
| --- | --- | --- | --- | --- |
| ready | 110.2 | 101.8 | 3.6 | 20 / 0 |
| scroll_1 | 178.2 | 169.8 | 64.0 | 16 / 0 |
| scroll_3 | 179.4 | 171.0 | 64.0 | 16 / 0 |
| scroll_10 | 179.9 | 171.3 | 63.9 | 20 / 0 |
| scroll_20 | 180.3 | 171.7 | 63.9 | 20 / 0 |
| scroll_30 | 180.4 | 171.8 | 63.9 | 20 / 0 |
| resized | 197.0 | 188.4 | 63.8 | 20 / 0 |
| cleared | 69.2 | 60.6 | 0.0 | 0 / 0 |

第 3 到第 30 段的 RSS 变化为 1.0MiB。此结果与固定缓存/对象数一起用于判断，不能只凭单点 RSS 断言泄漏。长滚动完整结果为 [soak-300000.json](benchmarks/soak-300000.json)。

cleared 是探针先清场景模型再调用真实 clear_cache 的结果，等待 worker 确认后采样。菜单仅清缓存时，当前目录元数据及可见图片仍有所有权，不应消失。cold 矩阵为保留磁盘给下一进程，仅在探针中直接清内存；其清理 RSS 与 warm 的显式清理不可混比。glibc 的空闲堆保留经独立 trim 实验确认后，仅在明确清理时归还，不做周期性 trim。

## 大图、动画与编码取舍

72MP（9000×8000）JPEG 和 120 帧 640×360 GIF 单独测量，见 viewer-before/after/final-ui.json。大图峰值从约 1082MiB 降至约 252MiB；首图约 323→283ms，切图后立即关闭约 313→21ms。去掉完整图像缓存、相邻预加载，future 结果消费后移动到 pixmap；JPEG 按原生 n/8 缩放显示 7875×7000，仍有约 55MP 像素。GIF 由 CacheAll 改为 CacheNone，3 秒快照约 147→43MiB，关闭后停止播放并释放对象。这组数据不等于所有格式或硬件解码峰值。

原 PNG 方案中，64MiB 缓存使固定滚动轨迹出现更多重读和重新编码，写入量确实上升，未丢弃这组不利结果：ui-png、independent-png。Qt 微基准中 RGB PNG 低压缩每张 73628B、100 次编码约 206ms；JPEG95 为 18466B、约 48ms，解码也从约 90ms 降到 25ms，平均通道绝对误差 1.54/255。只对 JPEG 源、无 alpha 的照片缩略图采用 JPEG95，其他格式继续无损 PNG；原始图片没有修改。透明度和磁盘往返有独立回归。

JPEG95 加半屏预取仍有约 32% 成功返回为预取/过期结果，因此进一步删除视口外预取及旧空项补投。最终固定轨迹的写入量、返回数量均在上表保留；缓存预算减少不等于每种轨迹都减少写入记账：重复打开时原版约 59MiB、最终约 129MiB，既有返回数量增加，也有较小缓存下的命中率下降；没有把这一项视为已优化完成。更及时显示当前图片是有效工作增加，不能只看总 CPU 或总字节就推断单张成本。

## 验证与限制

Release 全应用/测试/benchmark 编译通过；Qt Test **72 个结果通过，0 失败、0 跳过**，CTest 1/1。Clang 23、RelWithDebInfo、ASan+UBSan、detect_leaks=1、halt_on_error=1，同样 72 个结果、CTest 1/1 通过；未使用抑制文件，Qt SDK 动态库本身未插桩，未运行 TSan。日志见 [Release](benchmarks/validation-release.txt) 与 [sanitizers](benchmarks/validation-sanitizers.txt)。

旧九项、长图/全景图、完整/增量布局与宽度交错、对象池复用、240 个可见需求、有界队列、损坏图片终态、八种 EXIF、覆盖文件、快速切图、同路径在途覆盖、关闭重开、GIF、72MP 大图、加载/错误底栏及放大后的错误居中、六种排序、C locale、空目录/权限、主题和持续滚动均有针对性覆盖。新增可复现缺陷均记录真实 RED/GREEN；资源阈值和格式选择依靠实测，不人为破坏实现制造失败。

剩余边界：

- 缩略图和在途版本仍使用 mtime 毫秒值及大小，不能识别时间戳和大小均不变的覆写；没有为此每次散列整个原图。静态预览缓存已删除，重新打开会重新读取。没有实时目录监听，外部改动后的布局尺寸和排序需要重扫更新。
- 已过期排队扫描不会启动；正在执行的 std::sort 或单次 Qt 解码需安全返回，关闭预览不等待，析构仍等待唯一前景作业。没有通用强制取消框架。
- 不支持缩小解码的超大格式仍受 1GiB Qt 分配界限；缩略图路径也可能对过大且不可缩小读取的格式显示失败。没有实现分块大图解码。
- 单进程磁盘缓存为 128MiB/1000 文件高水位；多实例共享缓存的预算一致性未验证，未新增锁文件框架。预算指文件内容字节，不含文件系统 inode/块对齐开销。
- 目前矩阵是 JPEG 派生数据，PNG/WebP/损坏图只做定向回归；真实混合原片库、Windows/macOS、多显示器迁移与数小时压力仍需复验。Linux 专用探针已在 CMake 中限制平台。

下一步优先使用真实混合图库，补齐 cancelled_write_bytes 和设备级 I/O、实际重访轨迹及桌面帧时间采样，验证滚动锚点、排序后位置保留、跨屏 DPI 更新和错误反馈；分别量 PNG/WebP、大型非缩小格式的 I/O/工作内存，再决定是否需要更深改动。当前没有依据增加线程、预加载或缓存预算。保留完整/增量布局算法和最近菜单的既有少量重复，只有真实行为变更需要时再统一职责。

## 复现命令

生成必须使用新根目录；工具会拒绝混用不同源内容/存储模式。Python/Pillow 仅用于测试数据生成，不是应用运行依赖。

```bash
cmake -S . -B /tmp/iv-release -DCMAKE_BUILD_TYPE=Release -DCMAKE_PREFIX_PATH=/path/to/Qt/6.9.3/gcc_64
cmake --build /tmp/iv-release -j4
ctest --test-dir /tmp/iv-release --output-on-failure
python3 tools/benchmark.py generate --source /path/to/photo.jpg --root /tmp/iv-new --storage independent
python3 tools/benchmark.py run --exe /tmp/iv-release/imageviewer_benchmark --data /tmp/iv-new --output /tmp/iv-results --evict-files
QT_QPA_PLATFORM=offscreen XDG_CONFIG_HOME=/tmp/iv-soak-config XDG_CACHE_HOME=/tmp/iv-soak-cache /tmp/iv-release/imageviewer_benchmark /tmp/iv-new/300000 /tmp/iv-soak.json soak
```

原版本可用 `git archive a85a683` 解包到独立临时目录并以相同 Qt/Release 编译；使用当前 runner 的 `--revision a85a683` 记录受测版本。不要在当前工作区切回基线覆盖修改。原矩阵去掉 --storage independent、--evict-files 即为共享 inode 组。--viewer、--encode、--headers、--ui 提供大图/GIF、编码、元数据与 Qt 截图探针。

技术依据：[Qt Unbuffered](https://doc.qt.io/qt-6/qiodevicebase.html#OpenModeFlag-enum)、[Linux fadvise](https://man7.org/linux/man-pages/man2/posix_fadvise.2.html)、[glibc malloc_trim](https://man7.org/linux/man-pages/man3/malloc_trim.3.html)、[Qt 6.9.3 JPEG 实现](https://github.com/qt/qtbase/blob/v6.9.3/src/plugins/imageformats/jpeg/qjpeghandler.cpp)、[PNG 实现](https://github.com/qt/qtbase/blob/v6.9.3/src/gui/image/qpnghandler.cpp)。
