## 阶段与验收

1. 基线：提交可复现数据生成器和真实主窗口驱动。固定 1280×800、同一 Qt/Release/后端、同一轨迹；10k/50k/100k/300k 每规模分别首次空应用缓存和新进程重复打开。系统页缓存不清空，明确称应用缓存冷/暖。记录 RSS/PSS/HWM、CPU、proc I/O、首屏/扫描/稳定/滚动/重排/清理、元数据估算、逻辑像素预算、active/pool/队列；不能将共享图像逻辑字节相加当作物理内存。使用本地真实壁纸派生的可复现混合尺寸 JPEG，目录项独立，硬链接共享样本内容以控制测试磁盘占用；说明不能代表 30 万个独立原图的冷盘 I/O。
2. 正确性：复跑现有测试；验证失败结果、过期解码、快捷键焦点、快速切目录与关闭。需要修改时逐项 RED/GREEN、独立提交。
3. 资源：按基线确定瓶颈，先删除累计加载集合/重复列表与视口调用，再处理容量增长、64MiB 缓存、可见优先有界任务、磁盘清理、预览峰值。每项回归并记录数据，线程数不增加。
4. UI：原生工具栏、路径、排序/主题/SVG、无图/扫描/失败状态、轻量卡片和预览导航；与前三阶段提交分开，保持高 DPI 与快捷键一致。用 Qt 截图检查布局，并用相同基准量额外渲染成本。
5. 验收：重跑原矩阵和大图/GIF/长滚动；给出 100k/300k 实测，区分 O(N) 元数据、固定像素预算、allocator 保留内存与实际泄漏；记录限制及尚未解决风险。运行正确性和 ASan/UBSan，不推送。

不创建通用任务框架、数据库或大型依赖。性能探针仅在独立 benchmark 中运行，不在产品里增加轮询计时器。若需要读取私有状态，采用只读测试友元，不提升既有成员可见性。

## Standards

独立规范复核提出：排序模式在 UI 内为私有枚举，线程信号仍为 int 并有 0/1/2 常量；完整与增量布局存在重复算法；两处最近路径菜单有少量重复。这三项分别是类型边界建议及两项判断性气味。

主代理核实：排序接口及常量在任务起点已存在；本轮未新增裸模式接口，也不提升 private 可见性。两种布局路径及菜单重复同样为既有结构，未发现本轮引入的行为错误，不为消除形式重复引入包装或任务框架。probe 的友元用于统计及测试缓存隔离，未提升成员可见性。

## Spec

独立需求复核提出：不支持缩小解码且超过 1GiB 的图片会被拒绝；Windows 若返回反斜杠，basename 偏移可能不正确。前者是起点已有的 Qt 分配边界，保留为大图能力限制；本轮实测的 72MP JPEG 能正常显示。后者未复现，[Qt 使用通用 `/` 路径分隔符](https://doc.qt.io/qt-6/qdir.html)，当前输入来自 QDirIterator；不把这个假设当成已确认缺陷。未发现额外功能蔓延，有界队列、64MiB 预算、失败终态、会话过滤和 GIF CacheNone 均经复核。

复核统计：规范轴 3 项建议/既有结构，需求轴 2 项边界或待核实意见；没有据此确认新的本轮缺陷。具体未验平台和格式范围见最终结果报告。

最后一轮补充：`jpeg-prefetch` 实测 1 万图库有约 32% 的成功结果为预取或已过期，已删除上下半视口预取。`only_visible_requests` 实际 RED 为视口外 index 8；`scrolled_result_skips_old` 复现滚动后、帧合并前的旧空项补投，修复为补充请求也过滤当前相交范围。240 个可见需求测试通过显示真实视图确认尺寸，继续要求全部完成，不降低断言。

补充规范复核发现探针未单列空图结果，现增加 failed_results；decoded_count 是包含命中、失败的返回总数，其他三项只计成功，四项合计为总数。有效 JPEG 数据集没有失败结果。补充需求复核重申相同 mtime/size 覆写的缓存边界，并提出直接超量调用 loader 的风险。当前 UI 每次信用为 `64 - active_loading`，取消后队列数不大于 active_loading，因此提交数不超过实际剩余队列容量；240 个需求回归验证不会静默挂起。不为脱离当前调用契约的直接批量误用恢复 dropped/同步重投。缓存目录是应用独占目录，旧 .png 与新 .thumb 统一计入预算和清理，未增加旧格式读取回退。

最终预览状态核验：`image_viewer_window.cc:273,346` 在切图时保留旧底栏、失败时保留旧场景范围/缩放。新增状态回归与放大后失败的中心可见断言分别实际 RED（旧 image.png 信息仍在、错误文字中心不在视口），修复为清空加载状态、错误时设置自身范围并重置/居中视图。此改动不经过图库基准路径；预览另行复测。八种 EXIF 回归还扩展到第二个 loader 的磁盘往返，避免 JPEG 缓存改变方向或比例。
